# Greenleaf — интернет-магазин

Витрина и админ-панель магазина Greenleaf: каталог из ~220 товаров, поиск, корзина, оформление заказа
с доставкой или самовывозом, партнёрские цены, личный кабинет и полноценная админка для товаров,
медиа, заказов и пользователей.

## Состав

| Сервис     | Технологии                                                                 |
|------------|----------------------------------------------------------------------------|
| `backend`  | Java 21, Spring Boot 4, Spring Security (JWT), JPA/Hibernate, Flyway      |
| `frontend` | React 19, TypeScript, Vite, TanStack Query, Zustand; раздаётся через nginx |
| `postgres` | PostgreSQL 16 — данные, полнотекстовый и нечёткий (trigram) поиск         |
| `redis`    | Redis 7 — кеш каталога, корзины, лимиты запросов, отзыв токенов           |

```
greenlife-store/
├── backend/            Spring Boot API (порт 8080 внутри сети Docker)
├── frontend/           React SPA + nginx (проксирует /api и /uploads на backend)
├── seed/               Исходный каталог: products.json, фото и скрины из каталога
├── scripts/            smoke.sh — проверка API; build_seed.py — сборка seed из старого сайта
├── legacy/             Старая версия сайта (статичный React/Vite SPA) — для справки
├── docker-compose.yml
└── .env.example
```

## Запуск

Нужен Docker с Compose v2.

```bash
cp .env.example .env
# Обязательно поменяйте POSTGRES_PASSWORD, REDIS_PASSWORD, JWT_SECRET и ADMIN_PASSWORD.
# JWT_SECRET можно сгенерировать так: openssl rand -base64 48
docker compose up -d --build      # или docker-compose up -d --build
```

Сайт откроется на `http://localhost:${HTTP_PORT}` (по умолчанию 8080).
Если порт занят, поменяйте в `.env` вместе `HTTP_PORT`, `APP_PUBLIC_URL` и `CORS_ALLOWED_ORIGINS`.

> Переменные окружения из текущей сессии терминала важнее значений из `.env`.
> Если сайт поднимается не на том порту, проверьте `echo $HTTP_PORT`.

При первом старте с пустой базой:

- Flyway создаёт схему;
- импортируется каталог из `seed/` (около 40 секунд; прогресс виден в `docker compose logs -f backend`);
- создаётся администратор из `ADMIN_EMAIL` / `ADMIN_PASSWORD`.

Полезные команды:

```bash
docker compose ps                 # статус и healthcheck'и
docker compose logs -f backend    # логи API
docker compose down               # остановить (данные сохраняются в volume)
docker compose down -v            # остановить и удалить ВСЕ данные (база, загрузки, redis)
set -a && source .env && set +a && bash scripts/smoke.sh http://localhost:8080   # проверка основных сценариев API
```

`smoke.sh` берёт пароль администратора из `ADMIN_PASSWORD` и создаёт тестового пользователя, отменённый заказ
и удаляемый товар — запускайте его только на локальной копии, не на рабочем сайте.

Сменить пароль администратора: впишите новый `ADMIN_PASSWORD` в `.env`, поставьте `ADMIN_SYNC_PASSWORD=true`
и перезапустите `backend` — пароль будет приводиться к значению из `.env` при каждом запуске.

## Роли и авторизация

- **Гость** — каталог, корзина (в браузере), оформление заказа, отслеживание по номеру и телефону.
- **Пользователь** — плюс личный кабинет с историей заказов; корзина синхронизируется между устройствами.
- **Партнёр** — пользователь с флагом «партнёр» (ставит админ); видит и получает партнёрские цены.
- **Админ** — админ-панель `/admin`.

Как устроены токены:

- Access-токен (JWT, 15 минут) хранится только в памяти вкладки.
- Refresh-токен (30 дней) лежит в httpOnly-cookie, при каждом обновлении заменяется новым. Повторное
  использование старого refresh-токена отзывает всю цепочку.
- Выход, «выйти на всех устройствах», смена пароля, блокировка и смена роли отзывают выданные токены
  через Redis.
- **Забыли пароль:** на странице входа покупателю предлагается написать в WhatsApp магазина. Админ в разделе
  «Пользователи» нажимает «Новый пароль» — появляется временный пароль, его нужно передать покупателю.
  Все входы этого пользователя на других устройствах при этом сбрасываются.
- Вход, регистрация, оформление заказов и отслеживание ограничены по частоте; после нескольких
  неудачных попыток входа аккаунт временно блокируется.

## Карточка товара и админка

- Карточка: названия и описания на русском и казахском, краткое и полное описание, преимущества,
  способ применения, состав, предупреждения, характеристики, объём, бейдж, страница каталога,
  ключевые слова для поиска, розничная, партнёрская и старая цена, остаток.
- Медиа делятся на **фото**, **видео** (MP4, WEBM, MOV до 200 МБ), **скрины** (страницы из каталога)
  и **документы** (PDF, DOC, XLS, TXT; остальные файлы — до 25 МБ). У каждого файла есть заголовок,
  описание и alt-текст. Порядок меняется перетаскиванием, обложку можно назначить. Для изображений
  автоматически создаются лёгкие превью, оригинал остаётся доступен (например, в увеличенном просмотре).
- Вместо загрузки видео можно указать ссылку (YouTube, Vimeo или прямая ссылка на MP4) — вкладка
  «Медиа», раздел «Видео о товаре».
- В каталоге у каждого товара одна фотография. Клик по фото или карточке открывает окно товара:
  сначала видео, потом фото и скрины (листаются свайпом, стрелками и клавишами ← →). Окно открывается
  по ссылке вида `/catalog?product=<slug>`, кнопка «Назад» в браузере его закрывает.
- **Видео на главной** — два вертикальных ролика по очереди, по кругу, без звука до нажатия на кнопку звука:
  `frontend/public/video/greenleaf-1.mp4` и `greenleaf-2.mp4`. Чтобы заменить, положите новые MP4 (H.264)
  с теми же именами и пересоберите frontend. Настройка «Настройки сайта → Видео о компании» на главную
  больше не влияет.
- Категории (14): стирка, посуда и кухня, уборка, ароматы для дома, защита от насекомых,
  хозяйственные товары, волосы, тело и гигиена, лицо, макияж и парфюмерия, полость рта, детские
  товары, пластыри и бальзамы, питание и БАДы. Раскладка товаров по категориям — в
  `scripts/build_seed.py`; для уже работающей базы её применяет миграция `V3__regroup_categories.sql`.
- Внутри категорий — **виды товаров** (55 штук: «Шампуни», «Бальзамы и кондиционеры», «Подгузники»…).
  В каталоге они появляются подфильтрами, как только выбрана категория (и в боковой панели, и строкой
  под категориями), со счётчиками товаров. Вид сужает только свою категорию: «Шампуни» + вся категория
  «Уход за телом» — допустимое сочетание. Виды создаются и правятся в админке на странице «Категории»,
  вид товара выбирается в карточке товара. Раскладка — `TYPES` в `scripts/build_seed.py`, для
  работающей базы — миграция `V4__product_types.sql`.
- Фильтры каталога: категория → вид товара, цена (готовые диапазоны «до 2 999 ₸», «3 000 – 4 999 ₸»,
  «5 000 – 9 999 ₸», «от 10 000 ₸» со счётчиками или свои границы), бренды, «только в наличии»,
  «выбор Greenleaf». Все фильтры хранятся в адресе страницы (`?category=hair-care&type=shampoos&minPrice=3000`).
- Поиск в шапке работает с первой буквы: товары, виды товаров, категории и бренды обновляются при
  каждом введённом символе, совпадения подсвечиваются. Сначала ищутся точные совпадения по началу слов;
  если их нет — запрос в другой раскладке («ifvgeyb» → «шампуни»), затем поиск с опечатками.
- Редактор товара разбит на шаги «Основное → Описание → Характеристики → Фото и видео»; у каждого
  шага видно, что ещё не заполнено. Обязательные поля отмечены звёздочкой. Новый товар сохраняется
  черновиком и сразу открывает загрузку фото. Справа — живой предпросмотр карточки и список
  «Для публикации нужно».
- «Качество карточки» — оценка заполненности с подсказками, что добавить. Опубликовать товар без
  цены, категории или обложки нельзя.
- **Доставка:** бесплатно до двери при заказе по розничной цене от `FREE_DELIVERY_THRESHOLD`
  (по умолчанию 7 000 ₸), иначе — `DELIVERY_FEE`. При `FREE_DELIVERY_RETAIL_ONLY=true` заказы по
  партнёрским ценам бесплатную доставку по сумме не получают: партнёрам она бесплатна в день покупки
  дисконтной карты, и это менеджер отмечает вручную.
- Тексты акций (бегущая строка на главной, преимущества дисконтной карты, подарочные наборы) лежат в
  `frontend/src/content/promo.ts`, фото наборов — в `frontend/public/img/gifts/` (папки в `public/` не должны совпадать с адресами страниц, иначе nginx отдаст редирект).
- Данные покупателя для оформления заказа запоминаются отдельно для каждого аккаунта. У гостя — только
  до закрытия вкладки. При выходе из аккаунта браузер забывает корзину (она остаётся на сервере и
  вернётся при входе), контакты и личные данные.
- «Разобрать описание» — вытаскивает из сплошного текста преимущества, способ применения, состав
  и объём.
- Если два админа редактируют один товар, второй получит предупреждение, а не перезапишет чужие правки.
- Есть дашборд с выручкой, заказами, остатками, хитами и популярными запросами; заказы со сменой
  статусов и историей; категории, бренды, пользователи. Пока админка открыта, она раз в 30 секунд проверяет
  новые заказы: число новых видно в заголовке вкладки, при появлении нового заказа звучит сигнал.
- **Настройки сайта → Контакты магазина / Доставка и партнёрская цена** — телефон, WhatsApp, Telegram, Instagram, город, адрес, часы работы,
  стоимость доставки, порог бесплатной доставки и партнёрская скидка. Значения из `.env` действуют, пока
  их не поменяли в админке.
- При отмене заказа, который уже передан в доставку, админка спрашивает, вернулся ли товар: остаток
  возвращается на склад только если вернулся.
- **Защита от фейковых заказов:** на один телефон не больше `OPEN_ORDERS_PER_PHONE` неподтверждённых заказов
  (по умолчанию 3). `AUTO_CANCEL_NEW_AFTER_HOURS` — через сколько часов неподтверждённый заказ отменяется
  сам и возвращает товар на склад (0 — выключено).

## Удобства для покупателя

- **«Сделай подарок для себя и близких»** на главной — кнопка «Приобрети дисконтную карту» и один товар рядом.
  Покупателю, который вошёл и уже что-то покупал, подбирается товар по его покупкам (что берут вместе с ними,
  тот же вид, та же категория; купленное не повторяется). Остальным — случайный товар из категорий «Макияж и
  парфюмерия», «Уход за лицом», «Освежители и ароматы для дома» (список — `GIFT_CATEGORIES` в
  `CatalogService.java`). Показываются только товары с фото и в наличии; при каждом заходе — новый.

- **Избранное ♡ и «Вы недавно смотрели»** хранятся в браузере покупателя (регистрация не нужна):
  сердечко на карточке и на странице товара, страница `/favorites`, лента недавно просмотренных — на главной
  и внизу страницы товара. Скрытые и снятые с продажи товары из этих списков пропадают сами.
- **«Поделиться»** на странице товара: на телефоне открывается системное меню (WhatsApp, Telegram и т. д.),
  на компьютере — WhatsApp, Telegram и «Скопировать ссылку».
- **Шкала статуса заказа** (Принят → Подтверждён → Передан в доставку → Выполнен; у самовывоза без доставки)
  в кабинете, на странице «Где мой заказ?» и после оформления. Кнопка **«Повторить заказ»** в кабинете
  кладёт те же товары в корзину; если чего-то уже нет — корзина об этом предупредит.
- **Фото в WebP.** Для каталога из каждого фото делается лёгкая миниатюра WebP (в среднем ~16 КБ вместо ~170 КБ
  у исходного фото).
  Для уже загруженных фото они создаются автоматически при запуске бэкенда (один раз, в фоне).
- **Приложение на телефон (PWA).** Сайт можно установить на главный экран: в Chrome/Android — кнопка
  «Установить приложение» внизу сайта, на iPhone — подсказка «Поделиться → На экран «Домой»». Работает
  на HTTPS-адресе (и на localhost). Приложение кеширует только файлы сайта и фото — цены, наличие и
  заказы всегда загружаются свежими. Иконки: `frontend/public/icon-*.png`.

## Поисковики и превью ссылок

Сайт — одностраничное приложение, но поисковики и мессенджеры получают готовую страницу: nginx при каждом
открытии страницы подставляет в `index.html` (SSI) заголовок, описание, canonical, превью для WhatsApp/Telegram,
разметку schema.org (товар с ценой и наличием, «хлебные крошки», магазин с адресом и телефоном) и текстовую
версию содержимого — её видно долю секунды, пока не запустится приложение. Всё это собирает
`backend/.../site/SeoPages.java` из данных каталога.

- В поиск попадают главная, каталог, категории, виды товаров и товары; список — в `/sitemap.xml`.
- Результаты поиска, корзина, кабинет, админка и несуществующие страницы помечены `noindex`.
- Если бэкенд недоступен, страница всё равно открывается с заголовком по умолчанию.
- Проверить, как поисковик видит товар: [Rich Results Test](https://search.google.com/test/rich-results)
  и [валидатор микроразметки Яндекса](https://webmaster.yandex.ru/tools/microtest/).

## Уведомления о заказах в Telegram

1. В Telegram напишите [@BotFather](https://t.me/BotFather) команду `/newbot` и получите токен бота.
2. Напишите своему боту любое сообщение (или добавьте его в рабочую группу).
3. Узнайте ID чата у [@userinfobot](https://t.me/userinfobot) (у групп ID начинается с минуса; его также видно
   по адресу `https://api.telegram.org/bot<токен>/getUpdates` в поле `"chat":{"id":...}`).
4. Впишите токен и chat id в админке: «Настройки сайта → Уведомления о новых заказах в Telegram», сохраните
   и нажмите «Проверить». Можно задать их и в `.env` (`TELEGRAM_BOT_TOKEN`, `TELEGRAM_CHAT_ID`).

О каждом новом заказе придёт сообщение с номером, суммой, составом и контактами покупателя.

## Резервные копии

Копии включаются строкой `COMPOSE_PROFILES=backup` в `.env` (в `.env.example` она уже стоит), после чего
`docker compose up -d`. Выключить — оставить `COMPOSE_PROFILES=` пустым и выполнить `docker compose stop backup`.

Контейнер `backup` делает копию сразу после запуска и потом каждый день в `BACKUP_HOUR` часов
(по времени Алматы) — в папку `./backups` рядом с `docker-compose.yml`:

- `db-<дата>.dump` — база данных;
- `uploads-<дата>.tar.gz` — загруженные фото, видео и документы.

Копии старше `BACKUP_KEEP_DAYS` дней (по умолчанию 14) удаляются. Сделать копию прямо сейчас (работает и при
выключенных ежедневных копиях): `docker compose run --rm backup once`.

### Копия в облако (Яндекс Диск)

Копии на самом сервере не помогут, если сломается сервер, поэтому стоит включить отправку в облако:

1. Войдите в Яндекс ID владельца: [id.yandex.ru](https://id.yandex.ru) → «Безопасность» → «Пароли приложений» →
   создайте пароль для **«Файлы (WebDAV)»**. Обычный пароль от почты не подойдёт.
2. Впишите в `.env`:
   ```
   BACKUP_WEBDAV_URL=https://webdav.yandex.ru
   BACKUP_WEBDAV_USER=почта@yandex.ru
   BACKUP_WEBDAV_PASSWORD=пароль-приложения
   ```
3. Убедитесь, что копии включены (`COMPOSE_PROFILES=backup`), выполните `docker compose up -d backup` и проверьте `docker compose logs backup` — должна появиться строка
   `copied to the cloud`. На Диске появится папка `greenleaf-backups`.

На Диск каждую ночь уходит копия базы (хранятся `BACKUP_REMOTE_KEEP_DAYS` дней, по умолчанию 60) и новые
фото — уже отправленные фото повторно не загружаются и с Диска не удаляются. Подходит и любое другое хранилище с
WebDAV (Nextcloud, облако Mail.ru и т. п.) — нужен его адрес WebDAV, логин и пароль.

Если копию сохранить или отправить не удалось, в Telegram (тот же бот и чат, что для заказов) придёт
предупреждение.

Восстановление из облака: скачайте с Диска нужный `db-<дата>.dump` в папку `backups/`, а папку `uploads` —
целиком; дальше как ниже, только вместо распаковки архива скопируйте файлы в `/data/uploads`.

Восстановление:

```bash
docker compose stop backend
set -a && source .env && set +a
docker compose exec -T postgres pg_restore --clean --if-exists --no-owner \
  -U "$POSTGRES_USER" -d "$POSTGRES_DB" < backups/db-<дата>.dump
docker compose run --rm -T --no-deps --entrypoint sh -v "$PWD/backups:/backups:ro" backend \
  -c 'tar -xzf /backups/uploads-<дата>.tar.gz -C /data/uploads'
docker compose exec redis redis-cli -a "$REDIS_PASSWORD" FLUSHALL   # сбросить устаревший кеш
docker compose start backend
```

## Что лежит в Redis

| Ключи                         | Что это                                               | Срок жизни   |
|-------------------------------|-------------------------------------------------------|--------------|
| `gl:catalog:categories/brands`| Списки категорий и брендов                            | 1 час        |
| `gl:catalog:product`          | Полная карточка товара                                | 30 минут     |
| `gl:catalog:related`          | «Похожие» и «Покупают вместе»                         | 30 минут     |
| `gl:catalog:home`             | Подборки главной страницы                             | 10 минут     |
| `gl:catalog:search/facets`    | Результаты поиска и счётчики фильтров                 | 5 минут      |
| `gl:catalog:suggest`          | Подсказки в строке поиска                             | 5 минут      |
| `cart:*`                      | Корзины авторизованных пользователей                  | 30 дней      |
| `views:*`                     | Счётчик просмотров (сбрасывается в базу пачками)      | —            |
| `search:popular`              | Популярные поисковые запросы                          | —            |
| `ratelimit:*`                 | Ограничения частоты запросов                          | окно лимита  |
| `auth:*`                      | Отозванные токены                                     | до истечения |
| `gl:site:settings`            | Настройки витрины (видео о компании, контакты, цены)  | 1 час        |

Кеш каталога сбрасывается автоматически после любых изменений в админке. Если Redis недоступен,
сайт продолжает работать без кеша.

## Разработка без Docker

```bash
# База и Redis из compose (наружу проброшены на 127.0.0.1:5433 и 127.0.0.1:6380)
docker compose up -d postgres redis

# Backend на 8081
cd backend
DB_URL=jdbc:postgresql://localhost:5433/greenleaf DB_USER=greenleaf DB_PASSWORD=... \
REDIS_PORT=6380 REDIS_PASSWORD=... JWT_SECRET=... \
mvn spring-boot:run -Dspring-boot.run.arguments=--server.port=8081
# загрузки сохраняются в backend/data/uploads, seed берётся из ../seed

# Frontend на 5173 (проксирует /api и /uploads на http://localhost:8081;
# другой адрес задаётся через VITE_API_TARGET)
cd frontend
npm install
npm run dev
```

Тесты backend: `cd backend && mvn test`. Проверка типов frontend: `cd frontend && npx tsc -b`.

## Перед публикацией в интернет

- Задайте новые случайные `JWT_SECRET`, `POSTGRES_PASSWORD`, `REDIS_PASSWORD` и сложный `ADMIN_PASSWORD`.
- Поставьте сайт за HTTPS (например, Caddy или Traefik перед контейнером `frontend`) и оставьте
  `REFRESH_COOKIE_SECURE=true` (по умолчанию). `false` нужен только для локального `http://localhost` —
  иначе браузер не сохранит вход.
- Если HTTPS-прокси стоит на том же сервере, поставьте `HTTP_BIND=127.0.0.1`, чтобы порт сайта не был
  виден из интернета в обход HTTPS, и укажите в `TRUSTED_PROXY` адрес прокси (для прокси на самом хосте —
  `172.16.0.0/12`). Только этому адресу сайт верит, определяя IP покупателя для лимитов запросов.
- Пропишите реальный домен в `APP_PUBLIC_URL` и `CORS_ALLOWED_ORIGINS`. Из `APP_PUBLIC_URL` строятся
  `sitemap.xml`, `robots.txt` и превью ссылок в WhatsApp/Telegram/Instagram.
- После запуска добавьте сайт в Яндекс Вебмастер и Google Search Console и укажите им
  `https://ваш-домен/sitemap.xml`.
- Проверьте контакты и реквизиты на странице «Политика конфиденциальности» (`/privacy`): туда стоит
  добавить ИП/ТОО и БИН владельца магазина.
- Включите резервные копии (`COMPOSE_PROFILES=backup`) и отправку копий в облако (см. «Резервные копии»).
